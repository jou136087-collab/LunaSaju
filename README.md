# LUNE — 사주풀이

미니멀 에디토리얼 감성의 사주 명식 · 커플 궁합 사이트.
빌드 도구·서버·외부 라이브러리 없이 `index.html` 을 브라우저로 열면 바로 동작합니다.

참고 레퍼런스: Dribbble "Lune — Minimalistic Website" (달 모티프 · 대형 세리프 · 헤어라인 · 여백).
Dribbble 이 봇 접근을 차단해 원본 샷은 열람하지 못했고, 제목과 해당 장르의 관용적 언어를
근거로 재해석했습니다. 코드·에셋은 사용하지 않았습니다.

## 실행

```
index.html 더블클릭                        사이트 전체가 그대로 동작합니다
firebase emulators:start --only hosting    http://localhost:5000
```

`file://` 로도 명식·궁합·모든 화면이 정상 동작합니다.
**로그인만 안 됩니다** — Firebase 인증은 승인된 도메인을 요구하는데 `file://` 은 출처가 없기 때문입니다.
로그인까지 확인하려면 `localhost` 로 띄우거나 배포본을 쓰세요.

## 다른 PC에서 이어받기

```powershell
git clone https://github.com/jou136087-collab/LunaSaju.git
cd LunaSaju
```

이것만으로 **사이트는 바로 열립니다.** 아래는 무엇을 하느냐에 따라 추가로 필요한 것입니다.

| 하려는 일 | 필요한 것 |
|---|---|
| 화면 보기·수정 | 브라우저만 |
| 계산·명암비 검증 (`npm test`) | Node.js |
| 보안 규칙 검증 (`npm run test:rules`) | `npm install` + firebase-tools |
| 배포 (`firebase deploy`) | firebase-tools + `firebase login` |

```powershell
npm install -g firebase-tools
firebase login          # 프로젝트 소유 계정으로
npm install             # 규칙 테스트용 devDependency (사이트는 이거 없이도 동작)
```

`.firebaserc` 가 저장소에 들어 있어 `firebase use` 를 다시 할 필요가 없습니다.

저장소에 **없는 것**(각자 만들어짐): `node_modules/`, `.firebase/` 배포 캐시,
`users.json`(계정 내보내기 결과 — 이메일이 들어 있어 제외), 각종 `*-debug.log`.

> `assets/js/firebase-config.js` 는 **의도적으로 커밋**되어 있습니다.
> Firebase 웹 `apiKey` 는 비밀번호가 아니라 프로젝트를 가리키는 공개 식별자이고,
> 실제 접근 통제는 `firestore.rules` 가 합니다. 자세한 내용은 `SETUP.md`.

## 구조

**멀티페이지입니다.** 사이드바 링크가 실제 페이지 이동이며 SPA 라우터를 쓰지 않습니다.

```
index.html                   명식 짓기 (메인)
couple.html                  커플 궁합
method.html                  읽는 법
principle.html               계산 원리
legal.html                   저작권 · 고지 · 개인정보처리방침
admin.html                   방문 현황 (관리자 전용)

firebase.json                호스팅 · 규칙 · 에뮬레이터 설정
firestore.rules              접근 권한의 유일한 근거

assets/css/style.css         디자인 시스템 (토큰 · 다크모드 · 인쇄)
assets/js/
  calendar.js                천문 — 율리우스일 · VSOP87 태양황경 · 절기 · 시간대 역사
  data.js                    명리 기초 데이터 + 해석 문안
  saju.js                    명식 산출 (원국 · 십성 · 오행 · 대운 · 세운 · 공망)
  compat.js                  궁합 판정 (합충형해 · 배점 · 백분위)
  datefield.js               8자리 마스킹 입력 · 달력 팝오버 · 12지시 칩
  birthform.js               출생 정보 폼 (옵션으로 필드 노출 조절)
  store.js                   저장 어댑터 (localStorage + 클라우드 미러링 훅)
  firebase-config.js         콘솔에서 받은 값 (비어 있으면 백엔드 꺼짐)
  auth.js                    구글 로그인 · 프로필 동기화 · 방문 집계
  sky.js                     배경 캔버스
  layout.js                  셸 — 사이드바·상단바·푸터 생성, 테마·드로어·로그인 영역
  app.js                     index.html 전용
  couple.js                  couple.html 전용
  admin.js                   admin.html 전용
tools/                       검증 스크립트
```

**셸 마크업은 `layout.js` 가 만들어 넣습니다.** 사이드바를 5개 HTML 에 복붙하면 메뉴 하나
고칠 때 5곳을 고쳐야 하기 때문입니다. 각 페이지는 `<body data-page="...">` 로 자기가
누구인지만 알려주고, 현재 메뉴 표시(`aria-current`)는 layout.js 가 붙입니다.
메뉴를 추가하려면 `layout.js` 의 `NAV` 배열 한 곳만 고치면 됩니다.

해석 문안은 `data.js`, 궁합 문안은 `compat.js`(규칙 바로 옆), 계산 규칙은 `saju.js` 에 모여 있습니다.

### 입력 폼의 노출 필드

`LuneBirthForm.create(el, opts)` 의 `location` / `solar` / `hourChips` 로 조절합니다.

| 화면 | 태어난 곳 | 시간 보정 | 자시~해시 칩 |
|---|---|---|---|
| `index.html` (명식) | 감춤 → **서울 고정** | 감춤 → 보정 켬 | 감춤 |
| `couple.html` (궁합) | 표시 | 표시 | 표시 |

명식 화면은 입력을 최소로 두되, 감춘 사실을 결과에 그대로 밝힙니다 —
*"출생지 미입력 → 서울(동경 126.98°) 기준으로 진태양시 −32분 보정"*.
지역을 직접 고르려면 커플 궁합 화면을 쓰면 됩니다.

## 계산 방식

| 항목 | 방식 |
|---|---|
| 년주 | **입춘**(태양황경 315°) 기준. 1월 1일이 아님 |
| 월주 | 12절 기준. 황경 315°부터 30°씩 열두 구간 → 월지, 五虎遁 → 월간 |
| 일주 | 율리우스 적일 연속 계산 `(JDN − 11) mod 60`. 23시 이후는 야자시로 다음 날 |
| 시주 | 진태양시 2시간 구간 → 시지, 五鼠遁 → 시간 |
| 태양황경 | **VSOP87D 절단 급수** + FK5 보정 + 장동 + 광행차, ΔT(Espenak & Meeus) |
| 진태양시 | 출생지 경도 보정 `(경도 − 표준자오선) × 4분` |
| 표준자오선 | 1908–1911 UTC+8:30 / 1912–1954.3 UTC+9 / 1954.3–1961.8 UTC+8:30 / 이후 UTC+9 |
| 서머타임 | 1948–1951, 1955–1960, 1987–1988 시행 구간 −1시간 |
| 대운 | 양남음녀 순행 / 음남양녀 역행, 절입까지 일수 ÷ 3 |

### 정확도

한국천문연구원 공표 절기와 대조해 **전 항목 오차 1분 이내**입니다. (`#/principle` 화면에서
하드코딩이 아니라 실시간 계산으로 표를 그리므로, 엔진이 틀어지면 화면에 바로 드러납니다.)

저정밀 근사식(Meeus ch.25)은 오차가 0.01° ≈ 15분이라 **절입 경계 출생자의 월주가
통째로 뒤바뀝니다.** 그래서 쓰지 않습니다. 실측 개선폭은 최대 8분 → 1분.

일주 앵커는 `2000-01-01 = 戊午` 로 검증합니다.
(흔한 오기 주의 — 1984 는 갑자*년*이고, 1984-02-02 는 갑자일이 아니라 丙寅일입니다.)

## 궁합 점수

배점은 `compat.js` 가 유일한 근거이며, 화면에 어떤 규칙이 몇 점 걸렸는지 전부 공개합니다.

| 항목 | 배점 | 보는 것 |
|---|---|---|
| 일지 | 30 | 배우자궁. 육합·삼합·충·형·해 |
| 일간 | 25 | 천간합·충, 오행 상생상극, 상호 십성 |
| 오행 보완 | 25 | 한쪽의 결핍을 다른 쪽이 채우는가 + 일간의 힘이 상보적인가 |
| 나머지 기둥 | 20 | 년·월·시 지지 관계 |

**등급 경계는 임의로 정하지 않고 실제 분포에서 잡았습니다.** 무작위 6,000쌍을 돌려 보면
중립 조합이 50점 부근이고 65점이면 상위 10% 입니다. "85점 이상 = 천생연분" 같은 경계를
쓰면 실제로는 거의 나오지 않아 등급이 무의미해집니다. 화면에도 등급과 함께 백분위를 같이 씁니다.

배점을 고치면 `compat.js` 의 `PERCENTILES` 표도 다시 재야 합니다.
`tools/test-compat.mjs` 가 등급이 한쪽으로 쏠리지 않는지 검사합니다.

## 시인성

보조 텍스트의 명암비가 밝은 테마 2.91:1, 어두운 테마 3.70:1 로 WCAG AA(4.5:1) 미달이었습니다.
알파값을 눈대중이 아니라 역산해서 다시 잡았습니다.

| 토큰 | 역할 | 밝은 | 어두운 |
|---|---|---|---|
| `--ink` | 제목 | 16.2:1 | 15.6:1 |
| `--ink-strong` | 본문 보조 | 7.4:1 | 8.4:1 |
| `--ink-muted` | 라벨·캡션 | 5.2:1 | 5.5:1 |
| `--ink-faint` | 장식 전용 (본문 금지) | 3.4:1 | 3.4:1 |

두 테마의 알파가 다른 것이 정상입니다. 어두운 테마는 잉크가 밝아 더 낮은 알파로 같은 대비가 나옵니다.
본문 글자 크기 하한은 12px 로 두었습니다. `node tools/contrast-check.mjs` 가 CSS 를 직접
파싱해 검사하므로, 토큰을 만지면 바로 잡힙니다.

## 링크로 미리 채우기

```
index.html?d=1990-05-12&t=14:30&g=M
couple.html?a=1990-05-12,14:30,M,서울&b=1992-11-03,08:20,F,부산
```

| 페이지 | 파라미터 |
|---|---|
| `index.html` | `d` 생년월일 `YYYY-MM-DD` · `t` 시각 `HH:MM` · `g` `M`/`F` · `unknown=1` 시주 제외 |
| `couple.html` | `a`, `b` = `날짜,시각,성별,도시` (시각 대신 `x` 를 넣으면 시주 제외) |

URL 을 읽기만 하고 입력값을 주소창에 되쓰지 않습니다. 다만 **궁합 공유 링크에는 두 사람의
생년월일이 담기므로** 화면에 경고를 띄웁니다.

## Phase B — 백엔드 (배포 완료 · 로그인 켜기만 남음)

**라이브: <https://lune-saju.web.app>**

Firebase 프로젝트 생성 · Firestore(서울 리전) · 보안 규칙 배포 · 호스팅 배포까지 끝났습니다.
남은 것은 콘솔에서 **구글 로그인 제공자를 켜는 것 하나**뿐입니다 (CLI 로는 불가능) → **`SETUP.md`**

### 설정 전에도 사이트는 그대로 동작합니다

`firebase-config.js` 가 비어 있으면 `auth.js` 가 아무것도 하지 않습니다.
로그인 버튼이 나타나지 않고, 저장은 브라우저 안에만 남으며,
`index.html` 더블클릭(`file://`)도 여전히 됩니다.

이게 가능한 이유는 SDK 를 정적 `import` 가 아니라 **동적 `import()`** 로 가져오기 때문입니다.
정적 module 스크립트를 썼다면 설정이 없어도 `file://` 에서 CORS 로 깨졌을 겁니다.
**설정을 채운 뒤에는** 로그인에 진짜 출처가 필요하므로 `file://` 로는 열 수 없습니다.

### 저장 구조

`localStorage` 가 1차입니다. 로그인하면 `auth.js` 가 클라우드 값을 내려 심고,
이후 로컬 쓰기를 `Store.onWrite` 로 받아 되올립니다.
덕분에 `app.js`·`couple.js` 의 동기 호출부를 하나도 고치지 않았고, 오프라인에서도 동작합니다.

### 데이터 모델

| 경로 | 내용 | 접근 |
|---|---|---|
| `users/{uid}` | 이름·이메일·사진·가입/최근접속·방문수·저장한 명식 | 본인 읽기·쓰기 / 관리자 읽기만 |
| `users/{uid}/charts/{id}` | 저장한 명식 | 본인만 (관리자도 못 봄) |
| `stats/global`, `stats/day_YYYY-MM-DD` | `{ count, updatedAt }` | 누구나 **+1만** / 읽기는 관리자만 |

권한의 유일한 근거는 `firestore.rules` 입니다.
`firebase-config.js` 의 `adminUids` 는 화면에 메뉴를 띄울지 정할 뿐이라 신뢰하지 않습니다.
**둘 다** 같은 UID 로 맞춰야 합니다.

`npm run test:rules` 가 26가지 접근 시나리오를 에뮬레이터로 검사합니다 —

## 알려진 제약

- **양력 입력만** 지원합니다. 음력은 변환표가 필요해 넣지 않았습니다.
- **대한민국 출생 기준**입니다. 해외 출생은 해당 국가의 시간대·자오선 이력이 필요합니다.
- 야자시(23:00~24:00)는 **다음 날 일주로 넘기는 전통 방식**입니다. 자정 기준 유파와 결과가 다릅니다.
- 신강·신약은 월령 가중(월지 3 · 일지 2 · 기타 지지 1.5 · 천간 1)을 준 **간이 지표**입니다.
- 대운 나이는 출생연도 기준 세는나이 근사입니다.
- 신살은 공망만 넣었습니다.
- 글꼴은 Google Fonts 에서 내려받으므로 그 과정에서 브라우저 기본 정보가 Google 에 전달됩니다.
  생년월일 등 입력값과는 무관합니다.

## 배포

```
firebase deploy                 # 전체
firebase deploy --only hosting  # 화면만
firebase hosting:disable        # 즉시 비공개로 내리기
```

빌드 단계가 없어 소스가 그대로 올라갑니다.
백엔드를 떼면 GitHub Pages / Netlify 등 어디에나 그대로 올릴 수 있습니다.
